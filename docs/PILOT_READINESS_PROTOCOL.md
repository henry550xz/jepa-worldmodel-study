# Pilot readiness protocol

This gate runs eight training updates and two validation batches per arm, not a research pilot. All arms use FP32, batch32, history3, frameskip5,224px ViT width384 and the upstream AdaLN predictor/muP optimizer settings. Epoch budget for the proposed later pilot is2, checkpoint selection is the final fixed-budget checkpoint. Pixel adds its documented small decoder; parameter counts and extra compute are reported, not concealed.

`manifests/PUSHT_PARTITIONS.json` freezes episode IDs against the official archive hash. World train17,405, world validation512, probe train512/validation128/test124 plus4 reserved readiness fixtures; the21 upstream validation episodes are reserved. No window crosses episode partitions. SHA256 ordering, not Python randomized hashing, fixes assignment. Existing reproduction checkpoints have seen some of these training-archive probe episodes, so use new partition-trained checkpoints for the controlled pilot; reproduction checkpoints are not eligible for held-out scientific probe claims.

Readiness fits frozen linear and64-hidden-unit MLP probes on8 train episodes (16 frames each), selects fits on4 validation episodes, and tests on4 disjoint long readiness episodes (reserved from future pilot test use). These intentionally small fits validate interfaces, not physical accuracy. All methods use identical selected episodes and frame indices. Fit feature/target normalizers on probe training only. Actions retain upstream fixed normalization constants for all arms; those published constants may summarize the full archive and are a disclosed preprocessing convention, not freshly fitted held-out statistics.

Open-loop tests evaluate model-step horizons1,2,4,8,16,32 against pusher/block xy and circular block angle. For each, compare the same frozen probe on true-future encodings and predicted-future encodings. History frame indices0,5,10; first future15; grouped action prefix0:10 and future actions10:170. Verify short/long rollout prefix equality. Report velocities only in separately specified history probes; they are not identifiable from one RGB frame.

Ranking uses one frozen64-candidate bank (5 model steps each) with SHA256, simulator initial state/seed/prefix/goal, true endpoints and qualities stored once. Restore by reset plus complete prefix replay; dataset states lack block velocity/contact state and are not exact snapshots. Repeated and reordered rollout endpoint checks validate replay. The oracle rank must have zero regret; learned ranking is expected to be poor for8-update networks and is not a pass/fail accuracy target.

All three planning adapters use the SAME physical probe cost: mean squared four-coordinate error/512² + squared circular angle error/pi². Thus pixel is not forced to optimize JEPA latent distance. This requires equal labeled probe supervision for all methods and measures controllability with a learned physical readout, not native unsupervised planning. Pixel prediction remains temporal RGB training with no auxiliary latent objective. Native pixel-cost/latent-cost planning would be a separate confounded comparison and is not this matched pilot.

CEM:64 samples,8 elites,5 iterations; horizon5; execute1 model action (5 simulator steps); maximum10 replans, no simulator-based early stopping. Readiness executes2 replans to bound cost while preserving per-replan budget; candidate chunks8 bound VRAM. Simulator goal horizon5 is distinct from rollout horizon5 and execute prefix1. The frozen readiness bank uses simulator seed910001, separate from pilot validation/test seeds. Pilot goal banks must retain the same replay contract.

Training diagnostics are matched across arms: scalar train/validation losses, no upstream full-dataset visualization/open-loop diagnostics. Measure8 update timings, exclude first2 from steady throughput, and preserve optimizer/gradient checks. First-step action gradient may be zero from AdaLN-zero; check after warmup. Encoder/dynamics/decoder gradients remain mandatory. FP32 recommendations must consider both measured allocated and reserved peak VRAM plus driver headroom.

Full research training is explicitly NOT authorized by passing this gate. Exact launch commands are proposals until the user authorizes them.

## Executable evaluation profiles

`python -m study.evaluate_common RUN_ID --profile readiness` runs the bounded gate. `--profile pilot` accepts only a completed pilot manifest, fits probes using all512/128 train/validation episodes, evaluates all124 untouched probe-test episodes (with explicit unsupported-horizon skips), and evaluates50 frozen simulator seeds with10 replans each. Both use the same implementation and per-replan compute budget. The full profile is prepared but is not run by this gate.

Candidate-bank version2 generates goal actions using `goal_horizon` independently of candidate `rollout_horizon`; executed prefix remains independent. Banks and their true simulator scores are stored once, fingerprinted, and shared by all arms. Physical probe goals are supplied in physical coordinates equally to every arm; the model never sees true candidate outcomes while planning.

Probe normalizers mask features with training standard deviation≤1e-6 for every method. A feature constant in probe training has no identifiable readout coefficient; allowing a random coefficient divided by1e-6 to score a predicted activation would create arbitrary sparse-model errors. The mask is fit on probe training only and applied to both true and predicted representations. Active-feature counts are recorded. This is a common evaluator correctness fix, not tuning a world model or masking observed prediction errors.
